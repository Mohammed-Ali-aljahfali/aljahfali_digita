# مساعد الجحفلي — ربط Groq وتشغيل المعرفة

التنفيذ المحلي: 27 نوفمبر 2026. لم يُنشر إلى الإنتاج، ولم تُستخدم مفاتيح حقيقية أو تُرسل طلبات إلى Groq أثناء الاختبارات.

## الوظائف

- يظهر زر المساعد في صفحات الموقع العامة والمتجر والمنتج والسلة والدفع والدخول والحساب والسياسات ومركز المساعدة. لا يظهر داخل لوحة الإدارة.
- يجيب بالعربية عن المنتجات والباقات والأسعار المسجلة والعملات وخطوات الشراء والدفع والتسليم والخدمات العامة، ويستخدم صفحة المنتج الحالية وسياق المحادثة لتفسير المتابعات.
- يقرأ الخادم المنتجات والباقات والتصنيفات النشطة والسياسات والمقالات المنشورة. تُحدّث نسخته المؤقتة كل 30 ثانية عند الطلب. تكلفة الشراء وملاحظات الإدارة والمسودات ليست مصادر للمساعد.
- «متابعة طلباتي» تتطلب جلسة Supabase صحيحة. يعرض الخادم ملخص آخر خمسة طلبات يملكها المستخدم، في رد مباشر لا يمر عبر Groq. لا ينشئ المساعد طلبًا ولا يعدل حالة دفع أو يلغي شراءً.
- الرد المولّد يعرض روابط مصادر مأخوذة من سجلات الخادم، لا روابط يقترحها النموذج. الإجابات مولّدة وقد تخطئ؛ لا تُعد بديلًا عن السعر النهائي أو مراجعة الدعم.
- عند غياب Groq أو توقفه أو بلوغ الحد اليومي، يرجع الرد إلى دليل المتجر مع توضيح ذلك. عند غياب Supabase كليًا، يستخدم المتصفح الكتالوج المحلي ويبين أنه محفوظ وقد يحتاج تحديثًا. لا يختلق حسابًا أو طلبًا محليًا.

## التفعيل بالترتيب

1. أكمل إعداد المتجر على مشروع Supabase تجريبي وفق [دليل النشر](SUPABASE-DEPLOYMENT.md)، مع نسخة احتياطية قابلة للاستعادة. رابط المشروع ومفتاحه العام في `assets/js/store-config.js` مطلوبان؛ مفتاح Groq وحده لا يكفي.
2. بعد ترحيل المتجر `202611250001_secure_store.sql`، نفّذ كامل `supabase/migrations/202611260001_store_assistant.sql` على التجربة. يضيف مقالات المعرفة وعدادات الاستخدام وصلاحياتها، دون حذف المنتجات أو الطلبات.
3. من **Supabase → Edge Functions → Secrets**، أضف القيم التالية. الصق المفتاح في لوحة Supabase بنفسك، ولا تضعه في المحادثة أو ملفات الموقع:

| الاسم | القيمة |
| --- | --- |
| `GROQ_API_KEY` | مفتاح Groq الخاص بك |
| `GROQ_MODEL` | معرّف نموذج محادثة متاح في حسابك، يدعم `response_format: json_object`؛ مثال موثق: `llama-3.3-70b-versatile` |
| `ASSISTANT_AI_ENABLED` | `true` عند رغبتك في تفعيل طلبات Groq؛ غير ذلك يبقى دليل المتجر فعالًا |
| `ASSISTANT_ALLOWED_ORIGINS` | أصول الموقع المسموحة، مفصولة بفواصل ودون مسارات أو شرطة نهائية |
| `ASSISTANT_DAILY_AI_LIMIT` | حد طلبات Groq اليومية؛ الافتراضي `100` |
| `ASSISTANT_REQUESTS_PER_MINUTE` | حد طلبات المساعد لكل عنوان؛ الافتراضي `12` |
| `ASSISTANT_TIMEOUT_MS` | مهلة Groq بالميلي ثانية؛ الافتراضي `18000` |
| `ASSISTANT_RATE_LIMIT_SALT` | قيمة عشوائية سرية اختيارية لتجزئة معرّفات العدادات |

مثال أصول التجربة: `https://staging.example.com,http://127.0.0.1:4173`. استبدل نطاق المثال بنطاقك. عند الإنتاج استخدم النطاق الحقيقي فقط، مثل `https://aljahfalidigital.com,https://www.aljahfalidigital.com`.

تدعم الدالة متغيرات Supabase المدمجة `SUPABASE_URL` والمفتاح العام/الخادمي، سواء المفاتيح القديمة `SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` أو قواميس `SUPABASE_PUBLISHABLE_KEYS` و`SUPABASE_SECRET_KEYS` ذات المفتاح `default`. تبقى المفاتيح الخادمية داخل بيئة الدالة. مرجع الأسماء غير السري في `supabase/functions/.env.example`.

4. من مجلد المشروع، زامن حزمة المعرفة واختبرها، ثم انشر الدالة إلى مشروع التجربة المقصود:

```powershell
npm run assistant:sync
npm test
npm run check
supabase functions deploy store-assistant --project-ref YOUR_STAGING_PROJECT_REF
```

الدالة تقبل الأسئلة العامة دون تسجيل الدخول؛ لذلك إعدادها `verify_jwt=false` في `supabase/config.toml`. هذا خاص بـ`store-assistant` فقط. الطلبات الخاصة تتحقق من JWT عبر Supabase Auth قبل قراءة أي طلب. لا تغيّر إعداد دالة سند التحويل `upload-payment-receipt`.

5. افتح المتجر التجريبي وجرّب سؤالًا عامًا، ثم حساب عميل، ثم حسابًا مختلفًا. بعد اعتماد الاختبارات والسياسات والتكاليف، كرر الإعداد والنشر على الإنتاج وانشر ملفات الواجهة المعدلة. لا تنشر مجلد `supabase` أو ملفات البيئة إلى الاستضافة العامة.

التكامل يستخدم واجهة Chat Completions الموثقة لدى Groq، مع JSON و`max_completion_tokens=900` ودون أدوات تنفيذ. تحقق من توافر النموذج وحدود حسابك قبل التفعيل؛ لا يفترض الكود أن الاستخدام مجاني أو يفعّل ترقية مدفوعة. [توثيق Groq](https://console.groq.com/docs/text-chat)، [النماذج المدعومة](https://console.groq.com/docs/models)، [نشر دوال Supabase](https://supabase.com/docs/guides/functions/deploy)، [أسرار الدوال](https://supabase.com/docs/guides/functions/secrets).

## كيف تحدّث معلوماته

- **المنتجات والباقات:** عدّل الأقسام الحالية في الإدارة؛ المساعد يقرأ السجلات النشطة. قد تكون بعض أوصاف الكتالوج التاريخية قديمة، لذا راجع صحة الميزات والضمان قبل اعتمادها للعملاء.
- **السياسات:** لا يستخدم إلا السياسات المنشورة. إذا لم تُعتمد سياسة استرجاع، يذكر غيابها ويوجه للدعم بدل اختراع مدة.
- **معرفة المساعد:** قسم جديد في الإدارة لإضافة عنوان السؤال/الموضوع والإجابة المعتمدة. تبدأ المعلومة مسودة، وتدخل مصادر المساعد بعد اختيار «نشر المعلومة واعتمادها للمساعد». إلغاء النشر يخفيها بعد انتهاء ذاكرة الخادم المؤقتة.
- **المعلومات العامة الثابتة:** خطوات استخدام الموقع والخدمات الأساسية في `assets/js/assistant-knowledge.js`. بعد أي تعديل عليها شغّل `npm run assistant:sync` وأعد نشر الدالة والواجهة. فحص `npm run check` يرفض اختلاف نسخة الخادم عن الملف المرجعي.

رابط المقال العام: `assistant-help.html?id=UUID`. صفحة `assistant-help.html` تسرد المقالات المنشورة وتشرح عمل المساعد وخصوصيته. النص يُعرض كنص آمن دون تفسير HTML.

## الخصوصية وحدود التشغيل

المحادثة تبقى في ذاكرة صفحة المتصفح، وتمسح عند إعادة التحميل أو «محادثة جديدة» أو تغير الحساب. لا يوجد جدول يحفظ نص المحادثة. الأسئلة العامة وآخر ثماني رسائل عامة والمصادر المختارة قد تُرسل إلى Groq عند تفعيله. نتائج الطلبات الخاصة لا تدخل سجل Groq. توجد تنقيحات للأنماط الواضحة مثل المفاتيح والبريد وأرقام الطلبات، لكنها ليست بديلًا عن تجنب إدخال معلومات حساسة.

راجع سياسة الخصوصية المنشورة لتشرح مشاركة المحتوى مع Groq والاحتفاظ لدى مزودي الخدمة وفق إعداداتك. عدم حفظ النص في قاعدة بيانات التطبيق لا يثبت غياب سجلات تشغيل لدى الاستضافة أو مزود الذكاء الاصطناعي.

عدادات الاستخدام تحفظ بصمات مبهمة وأعدادًا فقط، وتزيل السجلات الأقدم من يومين عند الاستدعاء. قيد العنوان يعتمد عنوان الوكيل الذي تمرره البوابة ويجب التحقق منه في بيئة النشر؛ السقف العالمي اليومي هو الحاجز النهائي لعدد استدعاءات Groq. يبدأ يوم العداد وفق حدود UTC. الحد هو عدد المحاولات وليس ميزانية مالية أو ضمانًا ضد الإساءة. عند تعطل خدمة العدادات تتوقف طلبات Groq ويستمر الدليل.

المعرفة الحالية محدودة بأول 400 منتج و1500 باقة (حتى 20 باقة لكل منتج) و100 مقال؛ الكتالوج الحالي 34 منتجًا. تختار كل إجابة حتى ستة مصادر ذات صلة. التوسع الكبير قد يحتاج بحثًا مفهرسًا. الأسعار الآلية غير الدولارية تُحال إلى صفحة المنتج والدفع حتى لا يخمن المساعد تحويلًا غير موثوق.

## التحقق المنفذ

- 12 اختبار معرفة: أسماء عربية/إنجليزية، متابعة العملة، المقالات المنشورة، السياسات المفقودة، والأسعار المستقلة.
- 16 اختبار خادم: منع كشف طلبات عميل آخر، عدم إرسال بيانات الحساب إلى Groq، حدود المدخلات والاستخدام، إخفاء أسرار الأخطاء، روابط المصادر، وتعطل المزود.
- 11 اختبار واجهة محادثة: الإرسال والانتظار والإلغاء وإعادة المحاولة ولوحة المفاتيح، عرض النصوص بأمان، مسح المحادثة عند تغير الحساب، ومنع الأسرار الواضحة.
- اختبارات إضافية للاتصال الفعلي بين عميل المتصفح والدالة بمحاكاة الشبكة، ومحرر المعرفة وصفحة المقالات، وقيود PostgreSQL للنشر والعدادات.
- `npm test` و`npm run check` اجتازا التشغيل المحلي. السجل `test-results/assistant-full-tests.log`. لم تتصل الاختبارات بالإنتاج أو Groq.

ظهر زر المساعد في Chrome المحلي. تعذر إكمال الفحص البصري للمحادثة بسبب أخطاء أداة التحكم في موضع النافذة؛ لا ندعي اختبار جميع المقاسات فعليًا. اختبارات DOM تؤكد السلوك، لكنها لا تقيس المظهر. يلزم فحص الجوال والكمبيوتر واختبار رد Groq الحقيقي بعد الإعداد.

## التعطيل والتراجع

لتعطيل التوليد فقط، اجعل `ASSISTANT_AI_ENABLED=false` في أسرار Supabase. لإخفاء الواجهة، اجعل `assistant.enabled=false` في الإعداد العام وأعد نشره. لا تحذف المنتجات أو الطلبات أو جداول المتجر للتراجع عن المساعد. احتفظ بنسخة من مقالات المعرفة قبل أي تغيير. نقطة استعادة الملفات السابقة للإضافة: `.backups/pre-assistant-20261126.zip`؛ لا تمثل نسخة لقاعدة البيانات.
